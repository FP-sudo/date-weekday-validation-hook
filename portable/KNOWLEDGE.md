## 計算アルゴリズム（ツェラーの公式）

```
h = (q + floor(13(m+1)/5) + K + floor(K/4) + floor(J/4) + 5J) mod 7
```

| 記号 | 意味 |
|---|---|
| q | 日（1〜31） |
| m | 月（3〜14）※1月→13, 2月→14として前年扱い |
| K | 年の下2桁（西暦mod100）※1,2月は前年で計算 |
| J | 年の上2桁（西暦div100）※1,2月は前年で計算 |
| h | 0=土, 1=日, 2=月, 3=火, 4=水, 5=木, 6=金 |

### 検算例: 2026年4月29日
- q=29, m=4, K=26, J=20
- h = (29 + ⌊13×5/5⌋ + 26 + ⌊26/4⌋ + ⌊20/4⌋ + 5×20) mod 7
- h = (29 + 13 + 26 + 6 + 5 + 100) mod 7 = 179 mod 7 = **4 = 水**

よって **2026年4月29日は水曜日**。

## よくある間違いパターン（LLMが出しがち）

1. **前年の曜日感覚で書く** — 「去年の4月29日は金曜だったから今年も金曜」的ミス
2. **月末の繰り上がり誤認** — 5/31と6/1の曜日を取り違える
3. **2月29日を非閏年に書く** — 平年なのに「2月29日」と書いてしまう（閏年は4で割り切れる年、ただし100で割り切れて400で割り切れない年は除く）
4. **和暦/西暦の混同** — 令和と西暦を混同して計算する
5. **カッコ内の曜日だけコピペ** — 日付は変えたのに曜日を更新し忘れる

## チェック対象の具体例（○×）

### ○ チェックすべき
- メルマガ件名: 「【4/29(水)締切】...」
- LP本文: 「2026年4月29日(水)に開催」
- CTAボタン: 「5/6(水)までに申込」
- PS: 「次回は6/1(月)配信です」

### × チェック対象外
- 「来週の水曜日」（具体的日付なし）
- 「3日後」（相対日付）
- 「毎週月曜定例」（日付を伴わない）
